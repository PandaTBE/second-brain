# Руководство пользователя

**Second Brain 0.1.0 · обновлено 2026-11-06** · [English](user-guide.en.md) · [Все документы](README.md)

## 1. Что это и кому подходит

Second Brain — нативное приложение для macOS, которое собирает выбранные вами материалы в общую локальную память. Источниками могут быть сессии Codex, Claude Code и Qwen Code, заметки, страницы Notion, материалы GitHub и входящие Gmail/Яндекс Почты. Приложение хранит тексты и карточки в SQLite, ищет по ним через FTS5/BM25 и предоставляет эту память ИИ-клиентам через MCP.

Полезные сценарии:

- найти принятое в другом проекте техническое решение и проверить исходный диалог;
- передать Codex и Claude Code одну историю решений без ручного копирования целых чатов;
- искать по заметкам, документации репозитория и выбранным письмам в одном месте;
- сохранять контекст, который иначе остаётся в отдельных инструментах.

Практические преимущества — общий архив между клиентами, лексический поиск без
вызова модели, ссылки на источники и ревизии, явное управление модельной обработкой.
Неопубликованные сборки также поддерживают явно включаемые локальные embeddings
запроса. Это не обещание более качественных ответов для любого вопроса. Поиск по
словам может пропустить пересказ; модель может ошибаться; заполнение архива
занимает время.

Приложение не является облачной синхронизацией между компьютерами, заменой резервного копирования или подтверждённым профилем пользователя. Граф показывает источники и общие ключевые слова, а не доказанные смысловые или причинные связи. В версии 0.1.0 нативный интерфейс использует русский язык; документация доступна на русском и английском.

## 2. Требования и установка

### Готовый выпуск: без инструментов разработчика

Для **Mac с Apple Silicon и macOS 14+** скачайте
`Second-Brain-0.1.0-macos-arm64.zip` из **Releases → Assets** этого репозитория.
Архив содержит нативное приложение и его Python-сервис: пользователю не нужны
Xcode, Python, uv или исходники. Сборки для Intel в этом архиве нет. См.
[примечания к выпуску](releases/0.1.0.md).

1. Сверьте SHA-256 архива с файлом `SHA256SUMS` того же выпуска. Совпадение
   обнаруживает изменение файла, но само по себе не доказывает доверие к автору.
2. Распакуйте ZIP и перенесите **Second Brain.app** в **Программы** до настройки
   путей MCP.
3. Откройте приложение. Текущий пакет имеет ad-hoc подпись, **без Developer ID и
   нотарификации Apple**. Если macOS блокирует запуск и вы доверяете выпуску,
   используйте [инструкцию Apple](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac):
   **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**.
   Не отключайте Gatekeeper и другие системные меры защиты.
4. Добавьте свои источники и, при необходимости, ключ модели. Готовый выпуск не
   содержит заранее настроенного личного архива. Запросы macOS на доступ к папкам
   и Связке ключей рассматривайте в системных диалогах.

Данные готовой сборки хранятся в `~/Library/Application Support/Second Brain`,
вне пакета приложения. Перенос или замена `.app` не переносит архив, но при смене
пути приложения нужно обновить MCP-клиенты. Папка `.data` установки для разработки
остаётся отдельной и автоматически не копируется и не мигрирует.

После импорта локальный поиск работает без сети. Удалённые источники и облачная
генерация карточек используют подключения к соответствующим сервисам.

### Сборка из исходников для разработки

Для этого варианта нужны macOS 14+, инструменты Apple со **Swift 6.0+**,
Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Полный Xcode для исполняемых проверок CoreChecks не требуется; см.
[материалы Apple об инструментах разработчика](https://developer.apple.com/xcode/resources/).
Получите исходники и выполните из корня проекта:

```sh
xcode-select --install
uv sync --frozen --group dev
./scripts/build-app.sh
open "Second Brain.app"
```

Также доступен локальный запуск через `./start.command`. Приложение для разработки
использует исходники и `.venv`, а данные хранит в `.data` рядом с проектом.
Сохраните эту папку на постоянном месте; после её переноса пересоберите приложение
и обновите пути MCP. Этот вариант отличается от переносимого ZIP выше.

## 3. Первый запуск без расходов на модель

1. Откройте **Источники → Добавить источник** и выберите папку заметок или сессий.
2. У источника нажмите кнопку импорта. Проверка доступа и импорт — разные действия.
3. Откройте **Память** и найдите известную фразу из импортированного материала.
4. Откройте материал и проверьте текст, источник и ревизию.
5. При необходимости подключите MCP по разделу ниже.

Для этих действий модель и API-токен модели не нужны. При первой установке автоматическая обработка карточек выключена. Автоотслеживание локальных сессий включено, а периодическая сверка источников выключена. Не считайте эти значения описанием уже настроенной установки: свои текущие настройки проверяйте в приложении.

## 4. Подключение модели и карточки

Во вкладке **Модель и API** выберите провайдера и модель, проверьте подключение и сохраните настройки. Облачные подключения, включая **Qwen API**, используют API-токен. **Qwen / Ollama · локально** работает с загруженной локальной моделью без API-токена. Собственный OpenAI-совместимый API использует HTTPS и по умолчанию только публичные адреса. Опубликованный ZIP `v0.1.0` отклоняет внутренние адреса; настройка для корпоративной сети ниже доступна в неопубликованной сборке из исходников.

Для подключения по URL выберите **Свой API · OpenAI-совместимый**. Укажите публичный базовый адрес, например `https://api.example.com/v1`, без `/chat/completions`, API-токен и точный ID модели от провайдера. Нужна поддержка запросов `POST /chat/completions` в формате OpenAI. Загрузка каталога и проверка подключения необязательны: ID можно ввести и сохранить вручную, даже если `/models` недоступен или не содержит модель. После сохранения проверьте генерацию небольшой партией. В опубликованной `v0.1.0` приватные адреса не поддерживаются. Обычный HTTP и нестандартные порты по-прежнему не поддерживаются; для loopback-подключения локальной модели предназначена Ollama.

### Корпоративный API во внутренней сети — ещё не выпущено

**Обновлено 2026-11-05. Только сборка из исходников; в опубликованном ZIP `v0.1.0` этой настройки нет.** Для доверенного корпоративного сервиса выберите **Свой API · OpenAI-совместимый** и включите **Разрешить внутреннюю сеть для этого API**. По умолчанию разрешение выключено; оно сбрасывается при изменении базового адреса или провайдера. В запросах и сохранённых настройках ему соответствует поле `allow_private_network`; готовые преднастройки других провайдеров остаются только публичными.

Укажите базовый префикс, например `https://llm.example.internal/api/v2`, токен и точный ID модели. Приложение само добавит `/chat/completions`, получив `/api/v2/chat/completions`. Каталог загружать необязательно. Если сервис требует корпоративную сеть или VPN, подключитесь к ней; корпоративный адрес и токен не нужно публиковать в issue.

Разрешаются адреса RFC1918 IPv4, IPv6 ULA и CGNAT, кроме известных endpoint метаданных облачных машин. Loopback, link-local, неопределённые, multicast и остальные зарезервированные адреса остаются запрещены. Сохраняются HTTPS на порту 443, проверка сертификата исходного домена, закрепление проверенного IP и запрет перенаправлений. Если корпоративный сертификат не доверен CA-набору приложения, может появиться отдельная ошибка TLS; эта настройка не отключает проверку сертификата.

Облачный токен хранится в Связке ключей macOS, отдельно для выбранных провайдера и Base URL. Сохранённый секрет приложение обратно не показывает; отсутствие доступа к Keychain приводит к ошибке сохранения облачного секрета, а не к файловому запасному хранилищу. Для подключения модели Ollama токен и доступ к модельным credentials в Keychain не требуются.

Проверка подключения не создаёт карточку. OpenRouter использует авторизованный `/key`, Qwen API — документированный каталог Alibaba Cloud `/api/v1/models`, Ollama — список установленных моделей `/api/tags`. Другие облачные подключения используют `/models`. У SimpleClaw каталог публичный: успешная загрузка не доказывает правильность токена. У собственного API каталог также может быть публичным. Проверяйте генерацию выбранной моделью небольшой ручной партией карточек.

Карточки содержат резюме, ключевые слова, вопросы для поиска и факты с подтверждающими фрагментами исходного текста. Они дополняют архив; полный импортированный текст остаётся доступным, если создание карточки не удалось. Результат модели и его интерпретацию всё равно нужно проверять.

Показанная цена берётся из каталога провайдера, если он её отдаёт; неизвестная цена не означает бесплатность. Доступность модели, стоимость и условия обработки данных могут меняться. Приложение не устанавливает денежный лимит аккаунта провайдера.

Чтобы включить автоматические карточки:

1. В **Память → Изменить** откройте автоматизацию.
2. Включите автоматическое создание карточек и, при необходимости, периодическую сверку.
3. Укажите размер партии и число одновременных запросов.
4. Прочитайте предупреждение о повторяющихся API-расходах и сохраните настройки.

Размер партии по умолчанию — 10 материалов, допустимый диапазон — 1–50. Параллелизм по умолчанию — 10 запросов. В поле параллельности можно ввести любое положительное целое число без верхнего ограничения приложения. Ранее явно сохранённые значения сохраняются. Фактическое число одновременных задач не превышает размер текущей партии: например, параллельность 1000 при партии 10 позволяет одновременно обрабатывать до 10 материалов. Это ограничение работы за запуск, а не финансовый бюджет. Автоматические запуски и повторы тоже могут расходовать средства облачного провайдера. Для локальной Ollama фактическая генерация ограничена одним запросом одновременно; заданное значение сохраняется.

При ошибке карточки возможны два автоматических повтора: примерно через 60 и 300 секунд после соответствующих неудач. Всего — три автоматических запроса на ревизию материала: первоначальный и два повтора. Если локальная проверка паузы провайдера не допустила отправку, попытка не расходуется; отправленный запрос с ответом `429` расходует попытку. Бюджет сохраняется после перезапуска и неизменённого импорта. После его исчерпания карточка ждёт вашего действия. Блок повторов в **Памяти** показывает оставшиеся автоматические повторы, число карточек, требующих ручного действия, и состояние обработки: включена, выключена, на паузе или ожидает провайдера. Кнопка **Повторить все ошибки** после подтверждения возвращает все доступные ошибочные карточки в очередь и даёт каждой новый бюджет: первоначальная попытка и два повтора. Готовые карточки не меняются. При выключенных автокарточках или паузе очередь ждёт; кнопка не меняет настройки автоматизации и не снимает ограничение провайдера. Изменившийся материал получает новую ревизию и новый бюджет.

### Qwen API и локальная Qwen

**Инструкция подключения обновлена 2026-11-05.** Qwen API — облачный сервис Alibaba Cloud. Преднастройка использует Сингапур: `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`. Создайте API-ключ для соответствующего региона в [Model Studio](https://modelstudio.console.alibabacloud.com/). Учётная запись чата Qwen не заменяет этот ключ. Адреса других регионов можно настроить через собственный публичный HTTPS-провайдер. Каталог не запускает генерацию и не подтверждает доступность модели для вашего аккаунта. Если валюта или тарифная ступень не определены, цена показывается как неизвестная.

Для локального создания карточек:

1. Установите актуальную [Ollama для macOS](https://ollama.com/download/mac) и запустите её.
2. Загрузите модель, например `ollama pull qwen3:8b`. На [официальной странице](https://ollama.com/library/qwen3:8b) указан размер загрузки около 5,2 ГБ; рабочая память и контекст требуют дополнительных ресурсов. Скорость и потребление памяти зависят от Mac и модели.
3. В **Модель и API** выберите локальное подключение Ollama, обновите каталог, выберите точный ID загруженной модели и сохраните настройки. Поле токена не требуется.
4. Проверьте небольшую ручную партию карточек, затем при необходимости включите автоматическую обработку. Текущее облачное подключение само не переключается.

Ollama и веса модели устанавливаются отдельно: ZIP Second Brain их не содержит. Подключение работает только с фиксированным сервисом `127.0.0.1:11434` и загруженными моделями, без запасного перехода в облако. Облачные модели и удалённые псевдонимы отклоняются. Если Ollama не поддерживает требуемый локальный режим, обновите её. Используйте доверенный локальный сервер и учётную запись ОС. Импорт Notion, GitHub и почты по-прежнему обращается к соответствующим сервисам.

Локальные карточки создаются по одному запросу, а заданное число параллельных запросов сохраняется. Платы за API модели нет, но расходуются ресурсы Mac, память и электричество. Проверка точных цитат, бюджет повторов, поиск SQLite и MCP-память остаются прежними. Локальный адаптер запрашивает JSON без thinking-вывода, контекст 16 384 токена, до 1 024 выходных токенов и ограниченное время генерации. Эти настройки не являются результатом проверки качества или скорости.

### Паузы провайдера и ошибки карточек

При ответе `429` Second Brain прекращает допуск новых запросов карточек для выбранных провайдера, адреса API и модели. Уже допущенные запросы могут завершиться. Пауза сохраняется после перезапуска приложения. Если провайдер передал `Retry-After`, приложение учитывает этот срок; иначе ожидает 60 секунд. Распознанная ошибка исчерпания баланса или бюджета API-ключа требует действия пользователя вместо дальнейших автоматических запросов. Импорт, локальный поиск и MCP остаются доступны во время паузы провайдера.

В **Памяти** появляется блок **Карточки ожидают провайдера** с безопасным описанием причины и временем разрешённого повтора либо указанием проверить аккаунт. После устранения проблемы с балансом или бюджетом нажмите **Разрешить повтор**. Кнопка снимает паузу провайдера; включённая автоматическая обработка сможет продолжиться. Она не сбрасывает исчерпанные бюджеты материалов и не повторяет все прошлые ошибки. После устранения их причины используйте **Повторить все ошибки** отдельно.

После ограничения провайдера фактическая параллельность начинается с одного запроса и увеличивается после успешных запросов до сохранённого значения. Заданная настройка не меняется; приложение показывает временное снижение. Пауза провайдера может отложить повтор дольше срока отдельного материала. Общая пауза синхронизации остаётся отдельным управлением.

Диагностика карточек различает неподдерживаемый ответ или некорректный JSON, обрыв по лимиту вывода, отказ модели, неверную структуру карточки, отсутствие цитаты в источнике и утверждение вне своей цитаты. Компактный промпт запрашивает меньше коротких полей в пределах прежнего лимита вывода. Точная проверка доказательств сохраняется; исходный текст неудачной карточки остаётся доступен поиску. Диагностика не раскрывает полный ответ провайдера, а скрытых дополнительных запросов для исправления карточки нет.

## 5. Источники

Добавление подключения сохраняет настройки. Проверка доступа не равна импорту и не подтверждает, что все материалы уже находятся в памяти. Для первого заполнения используйте кнопку импорта у источника.

### Разрешения и исключения источника — ещё не выпущено

В **Источниках** нажмите кнопку с рукой у подключения и откройте **Разрешения
источника**. Пять независимых переключателей управляют импортом новых материалов,
поиском и просмотром в приложении, доступом MCP, локальной и внешней модельной
обработкой. Запрет импорта сохраняет разрешённый поиск по кешу; запрет внешней
обработки сохраняет локальный архив. Разрешение обработки само по себе не запускает
модель и не включает автоматическую очередь.

У старых источников без сохранённой политики все пять разрешений включены, чтобы
сохранить прежнее поведение. Общий флаг включения источника и отдельный
переключатель импорта почты продолжают действовать: разрешение импорта здесь не
включает приостановленный ящик или отключённый источник. Настройки автоматизации
и выбранная модель не меняются.

Доступ MCP отделён от локальной обработки. Codex или Claude может передать
результат MCP своей облачной модели, даже если внешняя обработка карточек в
Second Brain запрещена. Все подключённые MCP-клиенты используют одну политику
источника; проверяемой идентичности и отдельных прав для каждого клиента нет.

Для папок сессий и локальных заметок укажите относительные пути файлов или папок,
по одному в строке. Исключённая папка скрывает всё поддерево. Абсолютные пути, `..`
и маски отклоняются; допускается до 100 путей по 2048 символов. Для Apple Заметок
выберите исключения среди идентификаторов папок, уже выбранных при подключении.
Остальные коннекторы сохраняют свои реальные настройки страниц, репозиториев
и области входящих писем.

Изменив исключения, перед сохранением нажмите **Показать последствия исключений**.
Предпросмотр считает затронутые материалы кеша и показывает до 20 примеров;
он не предсказывает будущие импорты. Сохранённые исключения убирают материалы
из активной выдачи приложения/MCP и блокируют их дальнейший импорт и модельную
обработку. Исходные файлы и заметки сохраняются. Старые материалы Notes без ID
папки и локальные материалы с невосстановимым путём при соответствующих
исключениях скрываются до повторного импорта с известной областью источника.

Обновлённые MCP-процессы видят сохранённые политики без переподключения. При
обновлении перезапустите старые версии сервера: они не умеют применять новую
политику. Настройка не отзывает текст, ранее переданный клиенту или провайдеру;
запрет модельной обработки блокирует следующие отправки и сохранение результатов.
Исключённый кеш может оставаться в страницах SQLite и старых резервных копиях;
скрытие не означает криминалистическое стирание.

### Codex и Claude Code

Выберите папку сессий стандартным диалогом macOS. Обычные расположения — `~/.codex/sessions` и `~/.claude/projects`; разрешается другой явно выбранный каталог. Импортируются поддерживаемые JSONL-записи. Парсеры зависят от формата клиента, поэтому после его изменения могут появиться предупреждения или пропуски.

Отслеживание проверяет изменения примерно каждые 30 секунд. Распознаваемое завершение хода позволяет импортировать данные раньше; иначе используется пауза записи около 90 секунд. Это эвристика завершённости, а не гарантия конца всей беседы. Последующие сообщения обновляют память. Незавершённая последняя строка откладывается.

Суммарный лимит 128 МиБ для архивов сессий снят. При этом остаются ограничения отдельного JSONL-файла 64 МиБ, строки 1 МиБ, извлечённого текста, времени парсинга и обхода. Крупные файлы читаются потоком, неизменённые используют контрольные точки. Неуспешный или ограниченный проход виден в предупреждениях; отсутствие общего лимита не означает неограниченную загрузку любого файла.

### Qwen Code

Выберите **Добавить источник → Qwen Code** и папку `~/.qwen/projects`. При использовании `QWEN_HOME` / `QWEN_RUNTIME_DIR` укажите фактическую папку `projects`. Читаются только журналы JSONL в `chats/` и `chats/archive/`; можно выбрать и саму папку `chats`. Это локальная история диалогов, отдельная от подключения модели Qwen API или Ollama: для импорта токен Qwen не нужен.

Импорт сохраняет текст пользователя и ассистента, пропуская системные события, данные инструментов и блоки размышлений. Далее работают общие маскирование секретов, индекс SQLite и очередь карточек. Автоимпорт ждёт около 90 секунд без записи, проверяя изменения примерно каждые 30 секунд. Источник должен быть добавлен, автоимпорт включён, а синхронизация запущена. Незавершённые строки ждут следующего прохода. Чтение опирается на [официальный формат Qwen Code](https://github.com/QwenLM/qwen-code/blob/main/packages/core/src/services/chatRecordingService.ts); изменения формата клиента могут потребовать обновления.

### Папка заметок

Поддерживаются Markdown, TXT и JSONL. Проверка и импорт не переходят по символическим ссылкам. Для обычной папки сохраняются ограничения 16 МиБ на файл, 128 МиБ на проход и ограничение обхода. Отложенные файлы обрабатываются следующими проходами; файлы сверх индивидуального лимита пропускаются с предупреждением. Не выбирайте всю домашнюю папку ради нескольких заметок — используйте отдельный каталог с нужными материалами.

<a id="apple-notes-source"></a>

### Apple Заметки — ещё не выпущено

**Только сборки из исходников; в опубликованном ZIP `v0.1.0` этого источника нет.** Сначала откройте Apple «Заметки». В **Источники → Добавить источник → Apple Заметки** нажмите **Загрузить папки**, затем разрешите Second Brain доступ к Notes в системном запросе macOS. Поиск папок начинается только после нажатия кнопки. Если доступ был запрещён, проверьте **Системные настройки → Конфиденциальность и безопасность → Автоматизация**; см. [инструкцию Apple](https://support.apple.com/en-ie/guide/mac-help/mchl07817563/27/mac/27).

Выберите до 50 папок и нажмите **Добавить источник**. Импорт ограничен выбранными папками; вложенные папки выбираются отдельно. Через автоматизацию Notes читаются текст, заголовки, даты и стабильные идентификаторы заметок. Приложение не открывает базу Notes, не требует полного доступа к диску, не изменяет заметки и не читает вложения. Защищённые паролем заметки пропускаются, даже если они разблокированы в Notes.

Для первого заполнения нажмите импорт у источника. Если включена периодическая сверка источников, следующие проходы обновляют выбранные папки, пока Notes открыты. За проход проверяется до 50 заметок с сохранением продолжения; ограничения размера/времени и пропуски отражаются в статусе. Закрытие Notes или отзыв разрешения останавливает чтение до восстановления доступа. Удаление или защита оригинальной заметки автоматически не стирает прежнюю импортированную копию.

### Notion

1. Создайте внутреннюю интеграцию Notion с правом **Read content**.
2. Предоставьте ей доступ к нужным страницам через меню **Connections** в Notion.
3. В Second Brain выберите **Добавить источник → Notion** и введите токен интеграции.
4. Найдите страницы, загрузите дополнительные результаты при необходимости и явно выберите до 100 страниц.
5. Сохраните источник и запустите импорт.

Используется именно токен интеграции Notion, а не пароль аккаунта. Новые разрешения могут появиться в поиске не сразу. Вложенные страницы выбираются отдельно; базы данных и всё рабочее пространство автоматически не обходятся. Внешние вложения не загружаются. Неполный, усечённый или слишком большой ответ не заменяет предыдущую полную копию страницы.

### GitHub

В форме **GitHub** введите Personal Access Token, загрузите репозитории и выберите до 20. Можно включить документацию Markdown, issues и pull requests независимо. Фильтр списка не сбрасывает выбор; новые репозитории не подключаются автоматически.

Для fine-grained токена предоставьте доступ только к выбранным репозиториям: **Metadata: read**, **Contents: read** для документации, **Issues: read** для issues и **Pull requests: read** для PR. Организация может требовать одобрения токена.

Импортируются Markdown-файлы ветки по умолчанию и заголовки, описания, состояния и метки открытых и закрытых issues/PR. Комментарии, исходный код, diff, подмодули и символические ссылки не импортируются. Ссылки документации привязаны к снимку commit. Крупные архивы загружаются ограниченными пакетами с сохранением продолжения в SQLite; после полного обхода новый цикл подхватывает изменения старых материалов. Удалённый на GitHub объект может остаться в локальном архиве.

### Gmail и Яндекс Почта

Обе формы требуют полного адреса и **пароля приложения**, а не обычного пароля аккаунта. Сервер, TLS и порт подставляются автоматически. Пароли хранятся в Keychain. В опубликованной 0.1.0 эти формы Gmail/Яндекса не используют OAuth.

Для Gmail создайте отдельный 16-символьный пароль приложения с включённой двухэтапной аутентификацией. Возможность может быть недоступна из-за правил рабочего аккаунта или расширенной защиты. Пробелы между группами пароля Google убираются при сохранении. См. [официальную инструкцию Google](https://support.google.com/accounts/answer/185833?hl=ru).

Для Яндекса разрешите IMAP и использование паролей приложений в настройках почты, затем создайте пароль приложения типа **Почта**. Форма содержит ссылки на создание пароля и [официальную инструкцию Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

В форме выберите импорт входящих и период первоначальной загрузки: 30 дней по умолчанию, 90, 365 или вся история. Период применяется к дате получения на сервере. Загружаются только **Входящие / INBOX**. Импорт сохраняет продолжение, сначала обрабатывает новые письма и затем продолжает архив.

За проход обрабатывается до 50 писем в ограниченных окнах UID. Письма не помечаются прочитанными, не перемещаются и не удаляются. В памяти сохраняются заголовки и текст; HTML преобразуется в текст, вложения не индексируются и не передаются модели. Небольшое письмо при чтении поступает приложению целиком. **Письма больше 1 МиБ, включая размер вложений, пока пропускаются с предупреждением.** Внешние изображения и ссылки не открываются.

Кнопка проверки только считает входящие, не читая тела. Кнопка включения/паузы импорта у ящика сохраняет пароль, прогресс и уже загруженные материалы. Старые общие IMAP-подключения остаются доступными, но импорт для них по умолчанию не включается.

### Outlook / Microsoft 365 — ещё не выпущено

**Только сборки из исходников; в опубликованном ZIP `v0.1.0` этого источника нет.** Коннектор читает облачные ящики Outlook.com и Microsoft 365 через Microsoft Graph. Локальные файлы Outlook/PST/OST и Exchange на собственном сервере не импортируются.

1. Зарегистрируйте приложение Microsoft как public client и получите **Application (client) ID** по [инструкции](outlook-setup.md#russian). Client secret не используется.
2. Выберите **Добавить источник → Outlook / Microsoft 365**, заполните **Client ID приложения**, укажите, нужен ли импорт входящих, и период: 30, 90, 365 дней или вся история.
3. Нажмите **Войти через Microsoft**, затем **Открыть страницу Microsoft**. Введите показанный код на странице Microsoft, выполните вход и проверьте запрашиваемые права там. Пароль Microsoft в Second Brain не вводится; код входа не передавайте другим людям.
4. Проверьте показанную учётную запись и нажмите **Добавить источник**. Если выбран другой аккаунт, отмените вход и начните заново.
5. Запустите импорт у источника. Если включена периодическая сверка, следующие проходы продолжают архив; переключатель импорта ставит этот ящик на паузу.

Запрашиваются делегированные права `Mail.Read`, `User.Read` и `offline_access`. На стороне Microsoft `Mail.Read` даёт чтение ящика целиком; запросы Second Brain ограничены **Входящими**. Права отправки, удаления и изменения писем не запрашиваются. После добавления источника токены хранятся в Keychain, пароль обрабатывает Microsoft. Правила рабочего аккаунта могут требовать одобрения администратора или запрещать такой вход; обратитесь в IT, не обходите ограничения.

Ограниченный проход читает до 50 писем и сохраняет продолжение. Тела переводятся в текст; вложения и внешние изображения не загружаются. Импорт не помечает письма прочитанными, не перемещает и не удаляет их. При паузе уже загруженные материалы остаются в поиске. Удаление письма на сервере автоматически не стирает архивную копию. Если разрешение больше нельзя обновить, подключите источник заново; удаление источника очищает его локальные секреты и прогресс, а отзыв согласия у Microsoft выполняется отдельно.

## 6. Автоматизация, Dock и строка меню

Приложение должно быть запущено для автоматического импорта и создания карточек. Закрытие главного окна оставляет его в Dock и строке меню. Полный выход останавливает принадлежащий приложению локальный сервис и отслеживание; автозапуск при входе в macOS пока не настраивается.

Зелёный значок означает, что локальная служба готова к работе. Он остаётся зелёным в ожидании изменений и при паузе синхронизации. Это не подтверждение подключения внешнего MCP-клиента или успешной проверки каждого источника.

Общая кнопка остановки ставит на паузу автоматический импорт и автоматические карточки. Поиск, MCP, просмотр материалов и ручные действия остаются доступны. Уже начатый запрос может завершиться. Пауза сохраняется после перезапуска. Пауза отдельного ящика влияет только на его импорт.

Периодическая сверка по умолчанию использует интервал 15 минут, если её включить. Она обновляет обычные папки и удалённые источники с разрешённым импортом, а также может запустить ограниченную партию карточек при соответствующей настройке. В нативном интерфейсе эта настройка называется полной сверкой локальных источников; она также обслуживает подключённые удалённые источники.

<a id="quick-search"></a>

### Быстрый поиск из другого приложения — ещё не выпущено

Пока Second Brain работает, выберите **Быстрый поиск…** в меню строки состояния
или нажмите **Command–Option–Shift–Пробел**. Нативная панель **Быстрый поиск памяти**
переводит фокус в **Поиск в памяти** и показывает до восьми импортированных
материалов: источник, известную дату, ревизию и фрагмент. Доступны лексический,
семантический и гибридный режимы с прежними политиками нативного поиска и
диагностикой возврата к BM25. Пустой результат, загрузка и ошибка сервиса показаны
явно. Запрос ждёт 300 мс после ввода; устаревшая работа отменяется и не заменяет
результаты нового запроса.

**↑/↓** выбирают запись, **Return** выполняет **Открыть выбранный материал**,
**Esc** закрывает панель, **Command–Shift–C** выполняет **Скопировать контекст
выбранного материала**. Открытие показывает текущую запись в основном окне памяти.
Копирование перепроверяет разрешённый материал/ревизию и запрашивает только его
доказательства через `record_id` с бюджетом компактного JSON 6 000 символов.
Другая совпавшая запись не подставляется, embedding запроса для выбранного контекста
не создаётся. Открытие панели, ввод и выбор сами по себе не меняют буфер. Изменённый/
скрытый материал, ошибка запроса или устаревшая/закрытая панель отменяют действие.
Композиция метода ввода остаётся полю текста; нативные элементы имеют подписи
доступности и объявления состояния.

Для изменения сочетания выберите **Сочетание быстрого поиска…** в меню или
**Настройки сочетания** в панели. Нажмите **Записать сочетание**, введите новое,
затем **Сохранить сочетание**. Нужны минимум два модификатора, включая Command
или Control; зарезервированные комбинации и пара Control–Option отклоняются.
Esc отменяет запись, Tab переводит фокус. Новое сочетание регистрируется
до освобождения рабочего: при конфликте прежнее сохраняется, пункт меню доступен.
**По умолчанию** выбирает исходную комбинацию, применяемую после сохранения.
Настройки приложения меняются только после успешного явного сохранения.

Глобальная клавиша использует Carbon без разрешений Accessibility и отслеживания
ввода и не перехватывает глобальные нажатия. Закрытие основного окна сохраняет
работающее приложение и сочетание; полный выход останавливает их. Панель имеет
собственные запросы и выбор, независимо от основного списка памяти.

## 7. Поиск, карточки, граф и история

В **Памяти** нажмите **Материалы**, **Карточки**, **Ожидают** или **С ошибкой**,
чтобы выбрать фильтр лексического списка. Список подгружает по 30 материалов при
прокрутке. При фоновых изменениях приложение предлагает обновление, сохраняя
открытые страницы до него. В неопубликованной сборке семантический/гибридный режим
возвращает до 20 ранжированных материалов; для фильтров состояния и постраничной
истории выберите **По словам**.

FTS5 создаёт полнотекстовый индекс, BM25 ранжирует совпадения слов без вызова модели.
Если формулировка не находится, попробуйте имя проекта, конкретный термин, ошибку
или несколько вариантов слов. Откройте запись, чтобы проверить текст и цитаты.

<a id="semantic-search"></a>

### Локальный семантический и гибридный поиск — ещё не выпущено

В **Памяти** откройте кнопку с ползунками **Настройки поиска по смыслу** либо
**Модель и API → Настроить поиск по смыслу…**. Индекс по умолчанию выключен.
Установите Ollama и локальную модель с поддержкой embeddings отдельно; нажмите
**Обновить локальные модели**, выберите установленную модель, включите индекс
и сохраните настройки. Сохранение проверяет поддержку операции и размерность на
синтетическом тексте; модель карточек и её провайдер не меняются. Second Brain
не загружает веса и не подменяет модель облачной. Обычная чат-модель может
не поддерживать embeddings.

После включения работающее приложение индексирует разрешённые материалы
ограниченными фоновыми пакетами. **Индексировать следующий пакет** запускает один
пакет вручную. Учитываются общая пауза синхронизации и разрешение локальной
обработки каждого источника. MCP не строит индекс; готовые векторы читаются и при
закрытом приложении. Смена модели/digest, размерности или версии подготовки текста
создаёт новое поколение; изменённая ревизия материала не использует старый вектор.

У запроса доступны **По словам** (`lexical`, по умолчанию), **По смыслу**
(`semantic`) и **Гибридный** (`hybrid`). Два последних режима могут передавать
запрос явно включённой локальной embedding-модели. Гибридный режим независимо
получает словарных и векторных кандидатов, затем объединяет ранги через RRF.
Интерфейс показывает фактический режим и число готовых/доступных материалов.
При выключенном/пустом индексе или недоступной модели возвращается BM25 с причиной;
время локального запроса ограничено. Чтение памяти не запускает платную генерацию.

Неполный семантический индекс ищет только по готовым векторам; гибридный дополнительно
сохраняет словарных кандидатов среди остальных разрешённых материалов. Отсутствие
семантического совпадения не доказывает отсутствие сведений. Подготовленный ввод —
заголовок, перевод строки и сохранённый текст; если он длиннее 12 000 символов,
индексация фиксирует ошибку вместо незаметного усечения. Материал остаётся доступен
BM25. Оценка ранжирования, включая RRF, не означает вероятность истинности.

Если индексация остановилась с ошибками модели, запустите Ollama и повторно
сохраните выбранную embedding-модель. Успешная проверка возвращает ошибочные
задания текущего поколения в очередь, сохраняя готовые векторы; неудачная проверка
очередь не меняет. Затем запустите следующий пакет или дождитесь фонового писателя.
Это восстановление не сбрасывает бюджет платных повторов карточек.

Цель качества с настоящей моделью, холодный запуск и время embedding-запроса пока
не проверены: для оценки не было установленной модели Ollama. Отдельное измерение
сканирования 10 000 готовых синтетических векторов не подтверждает смысловое
качество или общую задержку пользовательского поиска.

**Граф и история** открывает локальную страницу в браузере. Нативные настройки приложения не используют WebView. Граф связывает материалы с источниками и общими ключевыми словами карточек; поиск и фильтры помогают исследовать архив. Граф ограничен снимком до 2000 материалов и явно сообщает об усечении, история доступна постранично. Требуется запущенное приложение. История отражает даты и текущие ревизии, а не полный журнал всех прежних версий текста.

<a id="mcp"></a>

## 8. Общая память через MCP

Выпущенная версия предоставляет четыре инструмента: `search_memory`, `get_record`,
`get_context_brief`, `get_sync_status`. Неопубликованная сборка добавляет
`get_evidence_bundle`, `get_facts`, `get_fact_history` только для чтения — всего семь.
Сервер не запускает импорт, создание/проекцию карточек или удаление источников;
отдельно запущенный клиентом MCP работает
и без приложения.

В неопубликованной сборке `search_memory(query, mode="hybrid")` или
`mode="semantic"` использует отдельно включённый локальный индекс. По умолчанию
сохраняется `lexical`. Ответ добавляет диагностику `search`: `requested_mode`,
`used_mode`, `fallback_reason`, покрытие `ready`/`eligible`/`partial`. Локальный
вектор запроса может создаваться без приложения; построение индекса по-прежнему
принадлежит его фоновому писателю. Вызовы трёх остальных инструментов не меняются.

Чтение записей, готовых карточек, доказательств, фактов, истории и ссылок оригинала
не вызывает настроенный API карточек и не расходует токены его модели. Локальные
embeddings запроса включаются отдельно, как описано выше. Агент всё равно может
расходовать входные токены, включая полученный текст в свой контекст; это зависит
от его клиента и провайдера.

<a id="evidence-bundles"></a>

### Пакет доказательств — ещё не выпущено

Попросите агента вызвать `get_evidence_bundle(query, budget_chars=12000)`, затем
составить ответ и сослаться на возвращённые `citation_id`. Обязателен `query`;
необязательны `source_id`, `project`, `date_from`, `date_to`, `budget_chars`,
`mode` (по умолчанию `hybrid`) и `record_id`. Четыре прежних инструмента сохраняют
обязательные аргументы; `get_context_brief()` по-прежнему вызывается без запроса.
Извлечение использует сохранённый текст/карточки и выбранный режим поиска
без генерации ответа.
Гибридный поиск может вызывать отдельно включённую локальную embedding-модель.
Инструкции источника остаются недоверенными данными.

Необязательный `record_id` ограничивает контекст одним текущим разрешённым
материалом без ранжирования и embeddings запроса. Фильтры источника/проекта/дат
сохраняются; отсутствующая или скрытая запись не подменяется другой. Диагностика
показывает `used_mode="record"`, но значения режима запроса остаются
lexical/semantic/hybrid. Сам запрос по-прежнему нужен для выбора полезного
фрагмента; без локализованного совпадения точная выдержка помечается как
неопределённая/неполная.

В **Память → Доказательства из памяти** (кнопка с кавычкой) просмотрите тот же
пакет с разрешениями нативного поиска. Укажите запрос, при необходимости источник,
проект и период UTC; нажмите **Найти доказательства**. Открытие окна может выполнить
поиск текущего запроса; запись в буфер происходит только по **Скопировать контекст**.
Копируется компактный JSON с цитатами, происхождением, дополнительными подтверждениями,
неполнотой и пометкой недоверенных данных. **Сверить с текущим материалом** повторно
проверяет цитату и окружающий контекст по текущей ревизии.

Перед копированием весь запрос выполняется заново: цитаты, дополнительные
подтверждения и счётчики обновляются с текущими разрешениями. Пустой результат,
ошибка, изменённый запрос или закрытое окно отменяют запись в буфер. Открытие и
проверка цитаты также обновляют пакет и проверяют доступный сейчас материал:
ID, URI, тип, ревизию и точный фрагмент. Копирование URI в деталях материала
аналогично перечитывает разрешённую запись. Уже показанный или переданный текст
отозвать нельзя.

Бюджет — 2 000–32 000 символов Unicode компактного JSON-пакета вместе с метаданными,
по умолчанию 12 000. Это не число токенов и не лимит внешней оболочки HTTP/MCP.
Пакет содержит до 20 основных цитат: точный фрагмент до 420 символов и до 100
символов контекста с каждой стороны. Одинаковые цитаты объединяются, сохраняя до
четырёх дополнительных подтверждений в `also_supported_by`, если позволяет бюджет.
Чередование источников распределяет место между ними. `incomplete` и `reasons`
сообщают об усечении, неоднозначном выборе цитаты, частичном поиске и других
ограничениях. Нелокализованный фрагмент и неоднозначное доказательство карточки
получают `quote_relevance="uncertain"`; интерфейс помечает их как требующие проверки
и объясняет ограничения по-русски. Исходные диагностические поля сохраняются в
копируемом JSON. Пустой результат не создаёт вымышленного ответа; дословность
подтверждает происхождение, а не истинность или релевантность утверждения.

Фильтр проекта точно сопоставляет явно сохранённое значение, например `cwd`/`project`
из метаданных сессии. Проект не выводится из расположения файла, заголовка или
текущей папки работы; неизвестный проект не совпадает. Фильтры применяются до
ранжирования. Дата берётся в UTC: сначала сообщение, затем изменение источника,
затем создание. Конечная дата `ГГГГ-ММ-ДД` включает весь день UTC; границы со временем
требуют часовой пояс. Материалы без даты в выбранный период не входят; время
импорта не подставляется вместо даты источника.

Даты цитаты разделены и могут отсутствовать. `imported_at` — сохранение текущей
текстовой ревизии; неизвестные старые значения остаются неизвестными. Повторный
импорт может заполнить явные даты/проект без смены неизменённой текстовой ревизии.
mtime локального файла — дата изменения источника; сессия использует последнее
сообщение чанка. IMAP берёт только Date с часовым поясом, Outlook — время получения
и изменение, только если оно предоставлено. Для файла GitHub дата неизвестна,
если её не даёт сам объект; активность репозитория не становится датой файла.

Поддерживаемый HTTPS-оригинал открывается после нажатия. Локальный файл показывается
в Finder; поддерживаемый указатель строк `#L…` по-прежнему показывает файл,
не исполняя его и не обещая перехода к строке. Для
непрозрачного ID Apple Заметок ссылка не выдумывается. Если материал, метаданные
или политика изменились, обновите пакет. Копирование не отзывает ранее переданный
агенту текст.

<a id="facts-history"></a>

### Факты и история решений — ещё не выпущено

Нажмите **Факты, решения и история подтверждений** рядом с поиском памяти. Окно
**Факты и решения** показывает до 20 объединённых утверждений с раскрываемыми
цитатами, происхождением и связями. Объединяются одинаковые формулировки после
нормализации Unicode NFC и удаления внешних пробелов, отдельно для фактов/решений.
Похожие формулировки не сливаются автоматически, исходные материалы сохраняются.

`source_supported` (**Подтверждается источниками**) означает наличие дословного
подтверждения формулировки, а не её истинность. `candidate` требует проверки;
распознанные обрамления ложного/предложенного утверждения, цитируемого примера
и блока кода сохраняют статус кандидата. Это консервативные эвристики, не полное
понимание языка. `possible_conflict` — предложенная связь, не доказанное
противоречие. `explicit_supersedes` требует узко распознаваемой явной положительной
формулировки с обоими решениями, верным направлением и контекстом. Более поздняя
дата сама по себе не заменяет решение; при изменении текста доказательство и
контекст перепроверяются.

По умолчанию требуется действующее разрешённое подтверждение. Включите
**Включать прошлые формулировки**, чтобы найти утверждения только со старыми
снимками: они получают пометку **Только в истории** (`historical_only=true`,
кандидат, неактивное подтверждение). Кнопки **История…** и **Загрузить более ранние
наблюдения** открывают постраничную историю. Время наблюдения в Second Brain
отделено от дат источника/сообщения. История начинается с `history_since` и не
восстанавливает ревизии, которых не было до включения функции. Старый снимок
не выдаётся за текущий текст.

Новые проверенные карточки проецируются в факты существующим писателем. Для уже
сохранённых готовых карточек нажмите **Обновить факты из карточек**: явный пакет
обрабатывает до 100 карточек без запроса модели, в том числе при паузе автоматической
синхронизации. Ограниченная фоновая проекция соблюдает паузу; чтение не запускает
проекцию. Извлечение в новых карточках использует промпт/схему версии 3 через
прежние выбранный API, очередь и бюджет попыток, без второго скрытого прохода модели.

MCP `get_facts(query="", limit=20, source_id=None, include_history=False)` возвращает
группы; `get_fact_history(fact_id, limit=50, before=None)` — наблюдения. Передайте
полученный `next_cursor` следующим параметром `before`, сохраняя устойчивые
`event_id`. Оба лимита допускают 1–100; нативные окна используют 20 групп и
50 событий на страницу. Пакет ограничен 32 000 байтами UTF-8 компактного JSON —
это другая единица, чем символьный бюджет доказательств. Ограниченные подтверждения
и связи отмечаются `truncated`, `evidence_truncated`, `relations_truncated`;
уточните источник/запрос или продолжите историю, не считая страницу полным архивом.

Текущие подтверждения, исторические снимки и цели связей проверяются по действующим
разрешениям/исключениям. Изменение текста перепроверяет цитаты; удаление источника
убирает его подтверждения и снимки. Действия истории/материала перечитывают доступ
перед показом текущего текста. Уже показанные/скопированные данные и старые копии
нельзя отозвать задним числом.

Во вкладке **Подключение MCP** скопируйте конфигурацию для Codex или Claude Desktop и добавьте её в соответствующий клиент. Экран генерирует настройки, но не устанавливает глобальное подключение автоматически и не проверяет чужое приложение. Успешное соединение подтвердите в самом клиенте.

Для готовой сборки сначала перенесите приложение в **Программы**, затем
скопируйте сформированные настройки из **Подключение MCP**. Команда указывает на
`Second Brain.app/Contents/Resources/Backend/SecondBrainHelper`, подкоманду `mcp`
и явную папку данных; системный Python ей не требуется.

Для **сборки из исходников** и установленных CLI выполните из корня проекта:

```sh
project_dir="$(pwd -P)"
codex mcp add second-brain -- "$project_dir/scripts/mcp-server.command" --data-dir "$project_dir/.data"
claude mcp add --scope user --transport stdio second-brain -- "$project_dir/scripts/mcp-server.command" --data-dir "$project_dir/.data"
```

Эти команды изменяют пользовательские настройки клиентов и дают доступ к этой памяти из других проектов. Не добавляйте токены источников или модели в конфигурацию MCP: серверу для чтения SQLite они не нужны. Сохраните остальные записи конфигурации клиента. В Claude Code проектный сервер может требовать подтверждения доверия.

После изменения пути проекта, обновления схемы источников или приложения переподключите MCP либо перезапустите клиент. После добавления Apple Заметок или Outlook перезапустите уже работающие MCP-клиенты Codex/Claude: старые процессы сервера не понимают новые типы источников. Все клиенты должны использовать один абсолютный `--data-dir`, если нужна общая память. Локальный порт нативного приложения к stdio-MCP не относится.

Пример запроса агенту: «Найди в Second Brain, почему мы выбрали этот способ авторизации, и покажи исходный материал». Сам факт подключения не гарантирует, что агент ищет память при каждом сообщении. Найденный текст — недоверенные данные источника, а не команда к выполнению.

## 9. Данные, резервная копия и удаление

Готовый выпуск хранит данные в `~/Library/Application Support/Second Brain`,
а сборка для разработки — в `.data` рядом с исходниками. В обеих папках находятся `memory.sqlite3`, `settings.json`, `sources.json`, `memory_schedule.json` и контрольные точки импорта в SQLite. Имена источников, пути и адреса аккаунтов тоже могут быть личными данными. Секреты находятся отдельно в Keychain; копирование папки данных их не переносит.

SQLite не зашифрован самим приложением. Маскирование известных шаблонов секретов выполняется до записи текста и отправки модели, но не гарантирует удаления всех персональных или чувствительных сведений. Модель получает импортированный текст при разрешённой обработке карточек. Настройте защиту диска и резервных копий под свой риск; см. [безопасность](../SECURITY.md).

Для согласованной копии базы используйте SQLite backup API. Не копируйте только активный `.sqlite3`, игнорируя WAL. Необязательный пример ниже требует Python 3; это не условие установки готового приложения. Для сборки из исходников замените `source` на путь `.data/memory.sqlite3` в папке проекта:

```sh
python3 - <<'PY'
import sqlite3
from datetime import datetime
from pathlib import Path

source = Path.home() / 'Library' / 'Application Support' / 'Second Brain' / 'memory.sqlite3'
target = Path.home() / 'Library' / 'Application Support' / 'Second Brain Backups'
target.mkdir(mode=0o700, parents=True, exist_ok=True)
target.chmod(0o700)
backup = target / (datetime.now().strftime('%Y%m%d-%H%M%S-%f') + '.sqlite3')
with sqlite3.connect(source.as_uri() + '?mode=ro', uri=True) as src:
    with sqlite3.connect(backup) as dst:
        src.backup(dst)
backup.chmod(0o600)
print(backup)
PY
```

Для согласованного комплекта базы и настроек завершите приложение перед снимком и копированием JSON: при активном изменении источников отдельные снимки могут не совпасть. Сохраните копии JSON-настроек в таком же защищённом месте. Они связывают записи с источниками; при переносе на другой Mac может потребоваться заново ввести секреты. Перед восстановлением полностью завершите приложение и MCP-процессы, сохраните резервную копию текущего состояния и восстанавливайте базу вместе с соответствующими настройками. Не заменяйте активную базу.

Удаление источника в приложении удаляет его локальные материалы из поиска/MCP, связанные карточки, секрет подключения и поддерживаемый прогресс этого источника. Оригиналы файлов, страниц, репозиториев и писем не удаляются. Исчезновение оригинала само по себе обычно не удаляет импортированную копию: база — локальный архив. Удаление из приложения не является гарантией криминалистического стирания SQLite, WAL или прежних резервных копий.

## 10. Решение проблем

| Симптом | Что проверить |
| --- | --- |
| Карточек нет, но текст ищется | Выбраны ли модель и токен; включена ли обработка карточек; не стоит ли общая пауза; есть ли ожидающие материалы. |
| Каталог загрузился, генерация не работает | ID модели, API-совместимость, право генерации и кредиты. Публичный каталог не подтверждает ключ. |
| DNS работает, но HTTPS/TLS обрывается | Маршрут VPN/прокси может не работать при исправном DNS. Если разрешено, сравните доступ к тому же API-домену через требуемый VPN и другую допустимую сеть. Сертификаты проверяются отдельно; не отключайте TLS-проверку и ограничения адресов. |
| Ошибка 429 / карточки ожидают провайдера | Прочитайте блок провайдера. При временном лимите дождитесь указанного срока; при распознанном исчерпании баланса или бюджета ключа исправьте проблему и нажмите «Разрешить повтор». Снижение параллельности не исправляет исчерпанный бюджет. |
| Ошибка ответа или доказательств карточки | Откройте материал и прочитайте точную причину. Исходный текст доступен поиску; устраните проблему модели или формата перед ручным повтором. |
| После ошибок повторы прекратились | Возможно, исчерпаны три автоматические попытки на ревизию. Разберите причину и разрешите ручную попытку. |
| Новая сессия ещё не появилась | Приложение запущено, источник выбран правильно, автоимпорт включён; подождите паузу записи или завершение хода. |
| Notion не находит страницу | Доступ интеграции через Connections, право Read content, задержка индексации Notion; повторите поиск. |
| GitHub показывает ошибку доступа | Выбор репозиториев токена, нужные read-права, одобрение организации; проверьте, не переименован ли репозиторий. |
| Папки Apple Заметок не загружаются | Откройте Notes, нажмите **Загрузить папки** и проверьте разрешение Notes в «Автоматизации». Защищённые паролем заметки намеренно пропускаются. |
| Outlook не входит | Проверьте зарегистрированный Client ID, настройку public client, согласие и правила организации. См. [инструкцию](outlook-setup.md#russian). Если код истёк, начните вход заново. |
| Gmail/Яндекс не входят | Полный адрес, пароль приложения, настройки провайдера и ограничения организации. Для Яндекса новый пароль может активироваться не сразу. |
| Не все письма загрузились | Только INBOX и выбранный период; большие письма пропускаются; продолжение обрабатывается следующими проходами. |
| MCP не видит память | Переподключите MCP, проверьте сгенерированную команду, общий data-dir, доверие клиента и импорт. Сборке из исходников также требуется её `.venv`. |
| Ошибки семантического индекса — ещё не выпущено | Запустите Ollama, проверьте установленную embedding-модель и сохраните её снова в настройках поиска: ошибочные задания вернутся в очередь. Слишком длинные материалы остаются лексическими до изменения ввода. |
| Факты пусты или видны только в истории — ещё не выпущено | Проецируйте готовые карточки кнопкой **Обновить факты из карточек**, проверьте разрешения источников; **Включать прошлые формулировки** используйте для исследования истории. Проекция не вызывает модель. |
| Приложение не стартует после переноса | Для готового выпуска проверьте целостность `.app` и обновите пути MCP. Сборке из исходников нужна прежняя папка проекта с `.venv` или пересборка. Проверьте разрешения macOS. |
| Граф не открывается | Нужен запущенный локальный сервис приложения; отдельно работающий MCP не обслуживает страницу графа. |

В публичную ошибку приложите версию, версию macOS, этап и минимальное синтетическое воспроизведение. Не прикладывайте `.data`, письма, сессии, Keychain-данные, полные HTTP-ответы или снимки личной памяти. Для уязвимостей используйте порядок из [SECURITY.md](../SECURITY.md).
